【输出文件】`stage_outputs/problem_contract.json`

你必须同时写入以下 workspace 文件：
- `input_schema.json`
- `solution_schema.json`
- `stage_outputs/problem_contract.json`

【两种执行模式】

- 若没有提供独立审计反馈，执行首次设计：根据事实来源生成完整的三个 contract 文件。
- 若提供了“当前独立审计反馈”，执行审计退回修订：先完整读取现有三个 contract 文件，再以现有版本为基线进行增量修改。
- 审计退回时，逐条落实所有 `blocking` finding 的 `required_change`；逐条判断 `warning`，不得静默忽略。
- 只修改解决 finding 所必需的内容，保留原契约中仍然正确的设计，不得无理由更换 solution 语义或重写无关部分。
- 即使 finding 只涉及一个文件，完成后也必须重新验收三个文件的业务语义与跨文件一致性。
- 不得修改 `problem.md`、`stage_outputs/intake.json`、`data/` 或审计结果文件，也不得开始算法设计。
- 当前修订成功写入后，旧审计意见不再代表当前版本；不要把更早的 contract 或 audit 历史带入输出。

【schema 设计要求】
- `input_schema.json` 与 `solution_schema.json` 必须是 JSON Schema Draft 2020-12 的合法 JSON 对象。
- input schema 描述 solving 阶段从 `data/` 组装出的规范化 `input.json`。
- solution schema 描述 problem-level semantic solution，不能暴露 x[i,j]、y[k,t]、interval_var、route_arc_binary 等算法级决策变量。
- schema 应包含足够字段让外部评测能判断硬约束、计算目标值或说明目标不可计算原因。

【stage_outputs/problem_contract.json 格式】
推荐结构：

{
  "problem_family": "routing/scheduling/assignment/packing/network_flow/inventory/production_planning/facility_location/mixed_combinatorial/other",
  "message": "简短说明",
  "files": {
    "input_schema": "input_schema.json",
    "solution_schema": "solution_schema.json",
    "expected_input": "input.json",
    "expected_solution": "solution.json"
  },
  "semantic_solution": {
    "primary_objects": ["业务解中的核心对象"],
    "required_fields": ["solution.json 必须包含的关键字段"],
    "algorithm_independence_notes": "为什么该格式不绑定具体算法"
  },
  "input_contract": {
    "required_entities": ["规范化 input.json 必须包含的实体"],
    "data_sources": ["data/ 中会被使用的文件或字段"],
    "normalization_notes": "solving 如何从 data/ 组装 input.json"
  },
  "checker_contract": {
    "entrypoint": "check(input_data, solution, data_dir='data')",
    "cli": "python feasibility_checker.py --input input.json --solution solution.json --data-dir data --output feasibility_result.json",
    "checks": ["会独立检查的硬约束和目标项"]
  },
  "assumptions": []
}

写完后必须自行验收：
- `input_schema.json` 和 `solution_schema.json` 可被 json.load 读取。
- `stage_outputs/problem_contract.json` 是合法 JSON 对象。
- 本阶段自检只验证以上三个 contract 文件；不得因 `input.json`、`solution.json` 或 `feasibility_result.json` 尚不存在而报错。
