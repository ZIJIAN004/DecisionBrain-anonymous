【环境】workspace 是当前 cwd；shell 上限约 __TIME_BUDGET__ 秒，solver 内部总时限必须更短。

【必须生成】
- from_data_to_input.py：读取真实 `data/`，通过 JSON 解析和结构化映射确定性生成 input.json 的可重复执行转换程序；完成后必须保留。
- input.json：符合 input_schema.json 的规范化输入，只能通过一次独立的 `python3 from_data_to_input.py` shell 调用生成。
- solver.py：读取真实数据、调用选定算法、生成并自检结果，必须通过独立的 `run_solver` Runtime 调用运行；不得用 shell 直接执行 solver.py。
- solution.json：符合 solution_schema.json 的完整业务语义解；只能由 Runtime 的 `run_solver` 执行 solver.py 生成；无候选和正式无解证明路径不生成该文件。
- Review 开启时：用 `run_solver` 实际执行 solver.py；然后调用 submit_solving_outcome(result, message) 提交小型结构化求解结果。工具会要求 Runtime solver receipt，并验收 solver_result 和当前 solution_schema.json，再写入 solver_result.json 与 stage_outputs/solving.json；不要用 write_file 或 shell 直接写 solution.json 或这两个正式文件。
- Review 关闭时：保持 Solving self-check 的 solver_result.json 和 stage_outputs/solving.json 写入行为。

无解证明规则：
- status=infeasible 时 objective、mip_gap、optimality、solution_file、feasibility_result_file 必须为 null。
- status=infeasible 时 infeasibility_proof 必须为：`{"proof_type":"exact_solver_status | solver_certificate","solver":"实际求解器","raw_status":"求解器原始状态","model_scope":"complete","hard_constraints_covered":["完整模型覆盖的硬约束"],"evidence":["日志、状态或证书来源"]}`，且不得生成占位 solution.json。
- 有候选解时 solution_file 必须为 solution.json、optimality 必须非空，infeasibility_proof 必须为 null。
- time_limit、unknown、no_solution_found、infeasible_or_unbounded 没有候选解时，objective、mip_gap、optimality、solution_file、feasibility_result_file 必须为 null，diagnosis 必须简要说明实际终态，infeasibility_proof 必须为 null。
- 局部子模型或分解子问题 infeasible、启发式未找到解、time limit、代码异常和资源不足都不构成 status=infeasible。
- 独立运行 solver.py 的 `run_solver` 只要超时，Runtime 会发布既有 `runtime_solver_outcome.json` 外部超时终态；不得修改实现后在同一轮再次运行 solver.py。若本次执行已完整写出符合 solution_schema.json 的候选，Runtime 会携带该候选；否则按既有无候选超时路径处理。
- unknown 只用于求解程序正常结束但原生求解状态无法安全映射为 feasible、optimal、infeasible 或 infeasible_or_unbounded；no_solution_found 只用于启发式或其他非证明性搜索正常结束但未得到完整候选；infeasible_or_unbounded 只用于求解器原生返回该混合状态。

【solved 最低标准】
- 不得使用 write_file、replace_in_file 或嵌入完整实例 JSON 的 shell 命令直接创建、重写或修补 input.json。from_data_to_input.py 不得硬编码或逐项复述实例数据；源结构已符合 schema 时必须原样序列化，确需转换时必须显式实现并验证必需字段、实体数量、ID 集合、数组/矩阵/时间序列维度和未声明转换字段逐值相等。转换失败必须非零退出且不得留下部分 input.json。
- 已形成可供独立审查的完整求解尝试；候选路径要求 solution.json 存在且合法，无候选和无解证明路径不要求 solution.json。
- `run_solver` 是 solution.json 的唯一产出途径；完成一次有候选或无候选的 solver 执行后，必须通过 submit_solving_outcome 提交上述结构。工具会校验对应 Runtime receipt，并在候选路径按当前 solution_schema.json 验收 solution.json。
- Review 关闭时，保持 Solving self-check 的直接文件写入和自检语义。
- 不得读取、运行或引用 feasibility_checker.py，不得生成或改写 feasibility_result.json；下游 Feasibility Reviewer 独立执行 checker 并决定是否拒绝及责任。
- executions 完整覆盖实际组件，package 调用与 algorithm_design 和 manifest 一致；fallback 不得静默发生。
- 写完所有文件后用 read_file 或 json.load 验收。

Solving 不得因自己怀疑候选不可行而隐藏本次产物，也不得声称 checker 已通过。语法、类型、API、文件、依赖、序列化和数值异常必须先在 Solving 内修复；decision=failed 只用于这些基础执行错误在阶段预算内仍无法形成可审查产物。shell timeout 以及正常返回的 time_limit、unknown、no_solution_found、infeasible_or_unbounded 必须使用 decision=solved 交给 Reviewer；shell timeout 不属于允许留在本阶段修复重试的基础执行错误。

[ENVIRONMENT] The workspace is the current cwd; the shell limit is approximately __TIME_BUDGET__ seconds, and the solver's total internal time limit must be shorter.

[REQUIRED ARTIFACTS]
- from_data_to_input.py: a reproducible conversion program that reads the real `data/` and deterministically generates input.json through JSON parsing and structured mapping; it must be retained after completion.
- input.json: normalized input conforming to input_schema.json, generated only through one separate `python3 from_data_to_input.py` shell call.
- solver.py: reads the real data, invokes the selected algorithm, and generates and self-checks results. It must be run through an independent `run_solver` Runtime call; do not execute solver.py directly with shell.
- solution.json: the complete business-semantic solution conforming to solution_schema.json. It may only be generated by Runtime's `run_solver` executing solver.py; do not generate this file on the no-candidate or formal-infeasibility-proof path.
- When Review is enabled: actually execute solver.py with `run_solver`, then call submit_solving_outcome(result, message) to submit a small structured solve result. The tool requires a Runtime solver receipt, validates solver_result and the current solution_schema.json, and then writes solver_result.json and stage_outputs/solving.json. Do not use write_file or shell to write solution.json or those two formal files directly.
- When Review is disabled: retain the Solving self-check behavior for writing solver_result.json and stage_outputs/solving.json.

Infeasibility-proof rules:
- When status=infeasible, objective, mip_gap, optimality, solution_file, and feasibility_result_file must be null.
- When status=infeasible, infeasibility_proof must be: `{"proof_type":"exact_solver_status | solver_certificate","solver":"Actual solver","raw_status":"Raw solver status","model_scope":"complete","hard_constraints_covered":["Hard constraints covered by the complete model"],"evidence":["Log, status, or certificate source"]}`, and a placeholder solution.json must not be generated.
- When there is a candidate solution, solution_file must be solution.json, optimality must be nonnull, and infeasibility_proof must be null.
- When time_limit, unknown, no_solution_found, or infeasible_or_unbounded has no candidate solution, objective, mip_gap, optimality, solution_file, and feasibility_result_file must be null; diagnosis must briefly explain the actual final state, and infeasibility_proof must be null.
- Infeasibility of a local submodel or decomposed subproblem, a heuristic's failure to find a solution, a time limit, a code exception, and insufficient resources do not constitute status=infeasible.
- Whenever the independently run solver.py times out in `run_solver`, Runtime publishes the existing externally timed-out final state in `runtime_solver_outcome.json`; do not modify the implementation and run solver.py again in the same round. If this execution completely wrote a candidate conforming to solution_schema.json, Runtime carries that candidate; otherwise use the existing no-candidate timeout path.
- unknown is only for a solve program that ends normally when its native solve status cannot safely map to feasible, optimal, infeasible, or infeasible_or_unbounded. no_solution_found is only for a heuristic or other non-proof search that ends normally without a complete candidate. infeasible_or_unbounded is only for the solver's native return of that combined status.
