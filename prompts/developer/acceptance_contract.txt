输出要求：

只输出一个 JSON 对象，不要输出多余文字，不要代码块标记。

JSON 格式如下：

{
"acceptance_status": "accepted | rejected | needs_review",
"feasibility_status": "feasible | infeasible | unknown",
"accepted": true,
"summary": "一句话说明最终验收结论",
"hard_violations": [
{
"source": "feasibility_result | business_spot_check | acceptance_audit | solver_checker_mismatch",
"layer": "contract_compliance | feasibility_checker_audit | result_consistency | business_spot_check",
"constraint": "违反的硬规则或约束名",
"detail": "具体对象、数值与差距"
}
],
"warnings": [
{
"source": "feasibility_result | solver_result | business_spot_check | acceptance_audit",
"check": "提示名称",
"detail": "不阻断验收的说明"
}
],
"objective_check": {
"reported_by_solver": null,
"recomputed_by_checker": null,
"abs_diff": null,
"rel_diff": null,
"within_tolerance": null,
"accepted_objective": null
},
"consistency_checks": {
"input_schema_valid": true,
"solution_schema_valid": true,
"checker_ran_successfully": true,
"feasibility_result_parseable": true,
"solver_claim_matches_checker": true,
"solver_objective_matches_checker": true
},
"business_spot_check": {
"performed": true,
"scope": [
"抽查了哪些业务对象、关键约束或高风险样本"
],
"passed": true,
"findings": [
{
"severity": "info | warning | hard_violation",
"check": "检查名称",
"detail": "检查结果"
}
]
},
"acceptance_rationale": "简短说明为什么 accepted、rejected 或 needs_review",
"audit_notes": [
"简短记录验收过程中发现的重要事实"
]
}

硬性要求：

* 不重新优化；
* 不生成新解；
* 不修改 input.json、solution.json 或 feasibility_result.json；
* 不放松业务规则；
* 不把“不保证全局最优”当作 infeasible；
* 不因为启发式算法或候选集有限而拒绝可行解；
* 不凭空假设缺失数据；
* 发现缺少关键验收证据时，使用 needs_review，而不是猜测 accepted；
* 只有明确硬违反才能 rejected；
* 只有 checker 通过、无阻断性 skipped_checks、无重大一致性冲突、business_spot_check 未发现关键问题时，才能 accepted。
