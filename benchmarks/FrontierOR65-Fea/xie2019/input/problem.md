# Problem Description

A container terminal operates a set of discrete berths and a pool of quay cranes (QCs) to serve incoming vessels. Time is divided into equal-length time steps organized into working shifts, where each working shift contains the same fixed number of time steps. The total set of time steps spans the entire planning horizon and is indexed sequentially: the global index of a time step equals its position within its shift plus the number of time steps per shift multiplied by one less than the shift number. For every within-shift position, there is a corresponding subset of global time steps that share that same within-shift index across all shifts.

Each vessel has an earliest feasible service time step and a latest feasible service time step, a least-cost berthing position (the berth index closest to the yard block where its containers are stacked), and an expected time of arrival agreed upon between the carrier and the terminal operator. Each berth has a start and an end of its available time steps. A known number of QCs are available at each time step across the terminal.

The handling of a vessel is governed by QC assignment profiles. The profiles are generated deterministically from the input data; they are not free choices that may be constructed differently by a solution method. Initialize a Python-compatible pseudorandom generator with `random_seed`. Generate the big profiles first and the small profiles second, using the same generator continuously across both groups. For one group, enumerate every duration `D` from `min_handling_shifts` through `max_handling_shifts`. For each duration, enumerate in lexicographic product order every length-`D` sequence whose entries range from `min_qc` through `max_qc`; an entry is the number of QCs used in that working shift. If the number of enumerated profiles is at most the requested group count, retain all of them in duration order and then lexicographic order. Otherwise, first use the generator to choose one profile uniformly from each duration bucket, visiting durations in increasing order. Then use one without-replacement sample from all remaining profiles, in their duration-then-lexicographic order, to fill the requested count. Concatenate the selected big profiles followed by the selected small profiles. The random choices and sample must have the same semantics and sequence as Python's `random.Random(random_seed).choice` and `.sample`; using another seed, restarting the generator between groups, or independently inventing profiles is invalid.

For each vessel, filter that concatenated list without changing its order: retain a raw profile only when `D * time_steps_per_shift <= b - a + 1`, where `[a,b]` is that vessel's feasible start window. Assign the retained profiles consecutive zero-based IDs `0,1,...` separately for that vessel. Thus a profile ID is vessel-specific, and the `profile` value reported for a vessel must refer to this deterministic filtered list. If service starts at global time step `h`, let `s = ((h - 1) mod time_steps_per_shift) + 1` be its one-based position within the current shift. For a retained profile with shift-level QC sequence `[q_1,...,q_D]`, its actual service duration is `(time_steps_per_shift - s + 1) + (D - 1) * time_steps_per_shift`: use `q_1` from the start time through the end of the current shift, then use each `q_2,...,q_D` for one complete subsequent shift. This profile construction and expansion defines the meaning of every reported profile ID.

The terminal must assign to each vessel exactly one berth, exactly one vessel-specific QC profile ID, and exactly one starting time step. The starting time step of each vessel must fall within the vessel's own earliest-to-latest feasible window and also within the availability window of the berth assigned to that vessel. The service completion time step of a vessel equals its starting time step plus the actual profile duration defined above minus one.

A vessel is considered to be occupying its assigned berth at every time step from its start through its completion. At most one vessel may occupy any given berth at any given time step, so the service intervals of vessels assigned to the same berth must not overlap. At each time step, the total number of QCs in use across all vessels being served must not exceed the number of QCs available at that time step. The number of QCs consumed by a vessel at a particular time step is determined by looking up the appropriate entry in its assigned profile: if a vessel started service at a particular starting time step under a particular profile, then at each global time step from the starting time step through the starting time step plus the profile duration minus one, the vessel uses the number of QCs specified by the profile at the relative position equal to the current global time step minus the starting time step plus one.

The goal is to minimize the total weighted deviation cost across all vessels. For each vessel, the deviation cost has two components: a penalty proportional to the absolute difference between the index of the assigned berth and the vessel's least-cost berthing position, scaled by a unit berth-deviation cost, plus a penalty proportional to the absolute difference between the assigned starting time step and the vessel's expected arrival time, scaled by a unit time-deviation cost.
