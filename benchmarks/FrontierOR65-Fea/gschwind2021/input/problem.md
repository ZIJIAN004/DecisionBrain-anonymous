# Problem Description

Given an undirected graph with a set of vertices and a set of edges, the task is to decompose the vertex set into the fewest possible groups, where each group forms an s-plex. An s-plex is a subset of vertices in which every member is adjacent to all but at most s minus one of the other members of the group; that is, the number of non-neighbors a vertex may have inside the group is bounded by s minus one. When s equals one, an s-plex reduces to a clique. The defining parameter s is provided as input, along with whether the decomposition is a partitioning or a covering, and whether connectivity of each group is required.

The input specifies the number of vertices, the number of edges, the list of vertices, the list of edges as unordered pairs of vertices, the value of the integer parameter s, whether the decomposition is a partitioning or a covering, and whether connectivity of each group is required. In the partitioning variant, every vertex must belong to exactly one selected group. In the covering variant, every vertex must belong to at least one selected group. When connectivity is required, the subgraph induced by each selected group must be connected, meaning there is a path within the group between every pair of its members using only edges of the original graph whose both endpoints lie in the group.

For each subset of vertices that qualifies as an s-plex (and is connected, if connectivity is required), the planner must decide whether to include it in the decomposition. Every vertex in the graph must appear in exactly one chosen group under partitioning, or in at least one chosen group under covering. A single vertex by itself always constitutes a valid group. The goal is to minimize the total number of groups used in the decomposition.
