# Problem Description

A collection of projects must be scheduled over a discrete planning horizon. Each project contains a set of jobs, including two artificial jobs with zero duration and zero resource consumption that mark the project's start and end. Every job belongs to exactly one project and can be executed in one of several available modes, where each mode specifies the job's processing duration and its consumption of each resource. Two types of resources exist: renewable resources, which have a per-period capacity limit that restricts the total consumption of all jobs being processed simultaneously in any single time period, and non-renewable resources, which have a global capacity limit that restricts the total consumption summed over all jobs across the entire horizon regardless of when they are scheduled. Each project has a release date before which none of its jobs may start. Direct precedence relationships between pairs of jobs require that whenever one job must precede another, the predecessor must finish (its start time plus its duration in the chosen mode) no later than the successor's start time.

The input data specifies the set of projects, the set of jobs with their project membership, the set of available modes per job with associated durations and per-resource consumption values, the capacity of each renewable and non-renewable resource, the release date of each project, the precedence relationships between jobs, and the identity of the artificial end job for each project. A critical path duration is computed for each project using the Critical Path Method while ignoring resource constraints. The earliest start time for each job is determined by forward propagation through the precedence graph using the Critical Path Method. An upper bound on each project's completion time is obtained from any known solution. A quantity called the maximum allowable total project delay is computed as the sum over all projects of the difference between the project's upper-bound completion time and the sum of its release date and its critical path duration. The overall planning horizon extends from time zero through the maximum over all projects of the sum of each project's release date, its critical path duration, and the maximum allowable total project delay. For each job in each mode, the latest allowable start time equals the job's project release date plus the project's critical path duration, minus the total duration of the longest path from that job to the project's artificial end job computed using the shortest-duration modes for all jobs along that path, plus the maximum allowable total project delay. The set of periods at which each job-mode combination may begin spans from that job's earliest start time through its latest allowable start time in that mode.

The scheduler must choose, for every job, exactly one mode and exactly one starting time from the job's allowable time window for that mode. For each time period and each renewable resource, the sum of the renewable resource consumption over all jobs that are being processed during that period must not exceed the resource's per-period capacity. A job is considered to be processing during a given time period if it was started at some earlier period within its duration window such that processing has not yet completed; specifically, a job started at a particular period in a mode with a particular duration is processing during each period from its start through its start plus its duration minus one. For each non-renewable resource, the total consumption across all jobs (each contributing the consumption of its chosen mode) must not exceed the resource's global capacity.

The goal is to minimize the total project delay, defined as the sum over all projects of the difference between each project's actual completion time (the start time of its artificial end job) and the sum of its release date and its critical path duration. A secondary tiebreaking term is added: a small positive coefficient multiplied by the overall makespan, where the makespan is at least as large as the completion time of every project's artificial end job. This hierarchical approach first minimizes the aggregate delay beyond the critical-path lower bounds and then, among schedules with the same total delay, prefers those with the smallest makespan.
