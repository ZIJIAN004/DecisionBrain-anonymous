# Problem Description

A construction logistics company provides containers arranged in a container unit (CU) on a construction site to accommodate various trades over the duration of a project. The project spans a fixed number of periods (typically calendar weeks). There is a set of containers and a set of trades. Each container has a start period and an end period defining the interval during which it is physically available on-site; outside this interval the container cannot be used. Each container also has a known set of adjacent containers, where adjacency is symmetric: if container A is adjacent to container B, then B is also adjacent to A. Adjacency reflects physical proximity in the CU, such as containers that are side-by-side, stacked, or connected by passageways or stairways. Each trade has a start period and an end period defining its active interval, a container demand specifying how many containers the trade requires in every period it is active, and a maximum dispersion value limiting how many separate groups (clusters) of containers the trade will tolerate.

The input data therefore specifies: the number of periods in the project, the full list of containers with their availability intervals and adjacency relationships, and the full list of trades with their activity intervals, per-period container demands, and maximum dispersion values.

The company must decide, for each trade in each period the trade is active, exactly which containers from those currently available on-site are assigned to that trade. In every period, each trade must be assigned exactly the number of containers equal to its demand, and each container may be assigned to at most one trade in a given period. Crucially, the containers assigned to a given trade in a given period must be arranged so that they form no more than the trade's maximum dispersion value of adjacency-connected groups. Two containers assigned to the same trade in the same period belong to the same group if one can reach the other through a chain of adjacent containers, where every container in the chain is also assigned to that trade in that period. The trade's assigned containers thus partition into connected groups under the adjacency relation, and the number of such groups must not exceed the trade's dispersion limit.

Whenever the set of containers assigned to a trade changes from one period to the next (during the trade's activity interval, after its first period on-site), the company incurs a re-assignment: any container that is newly brought into the trade's assignment in the current period - whether it was on-site but assigned elsewhere in the previous period, or has just become available on-site - counts as a change relative to the previous period. The first period in which a trade is active does not count as a re-assignment, since it constitutes the trade's initial move-in.

The objective is to minimize the total number of re-assignments across all trades over the entire project horizon - that is, the total number of (trade, period) pairs, excluding each trade's first active period, in which the trade's container assignment differs from the previous period.
